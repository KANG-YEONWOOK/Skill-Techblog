# techblog

자료를 읽고 그 핵심을 한국어 기술 블로그 아티클로 쓴다. 독자는 자료의 분야를 아는 개발자이고, 글은 토스·카카오·당근 기술 블로그에 실린 글처럼 읽혀야 한다.

입력: $ARGUMENTS

## 인자 해석

- 어투: `casual`, `Casual`, `해요체`가 있으면 Casual. `default`, `Default`, `합니다체`가 있거나 어투 지정이 없으면 Default.
- `-o <경로>`: 출력 파일. 없으면 현재 작업 디렉터리에 글 주제를 나타내는 영문 kebab-case 이름(예: `cache-invalidation-latency.md`)으로 저장한다.
- `--retone`: 입력 파일을 완성된 아티클로 보고 6단계(어투 적용)만 한다. 출력 경로가 없으면 `<입력 이름>.<casual|default>.md`.
- `--keep-work`: 작업 파일을 지우지 않는다.
- 나머지는 자료(파일 경로, URL)와 추가 지시(독자, 분량, 강조할 부분)다. 자료가 없으면 대화에 붙여넣은 텍스트를 자료로 쓴다. 그것도 없으면 무엇을 정리할지 묻는다.

## 파일

- 출력: `<이름>.md`
- 작업 파일(출력 파일과 같은 폴더): `<이름>.facts.md`(fact sheet), `<이름>.draft.md`(Casual일 때만 쓰는 Default 초안). 7단계에서 지운다.

## 스크립트 실행

- 스크립트는 Bash 도구로 실행한다. Windows는 `python`, macOS와 Linux는 `python3`를 쓴다. 경로는 큰따옴표로 감싼다. 한 번에 명령 하나만 실행하고 `;`, `&&`로 다른 명령(`cat` 등)을 이어 붙이지 않는다. 참고 문서는 Read 도구로 읽는다.
  - 문체 검사: `python "${CLAUDE_SKILL_DIR}/scripts/lint_ko.py" "<글>" --tone default --facts "<이름>.facts.md"`
  - 어투 검사: `python "${CLAUDE_SKILL_DIR}/scripts/tone_check.py" "<이름>.draft.md" "<이름>.md"`
  - 작업 파일 삭제: `python "${CLAUDE_SKILL_DIR}/scripts/tone_check.py" --cleanup "<이름>.facts.md" "<이름>.draft.md"`
- Python이 없거나 Bash를 쓸 수 없으면 `references/rubric.md`의 Gate와 자동 측정 항목을 직접 세서 같은 기준으로 점검한다.

## 작업 순서

### 1. 자료 읽기

- PDF: Read 도구로 읽는다. 한 번에 읽히지 않을 만큼 길면 `pages`로 나눠 마지막 쪽까지 읽는다. 표, 그림 설명, 부록의 수치도 본다.
- URL: WebFetch로 가져온다. HTML은 "요약하지 말고 본문을 그대로 돌려 달라"고 요청하고, 길면 절 단위로 나눠 요청한다. PDF URL은 WebFetch가 로컬에 저장한 `.pdf` 파일을 Read로 읽는다.
- 자료가 여러 개면 모두 읽는다.

### 2. fact sheet 쓰기

`<이름>.facts.md`에 적는다. 본문의 수치와 주장은 이 파일에서만 가져온다.

- 자료 정보: 제목, 저자 또는 기관, 연도, URL
- 문제와 배경: 자료가 풀려는 문제, 기존 방법의 한계
- 방법: 핵심 아이디어, 동작 순서, 실험 설정(모델, 데이터, 조건)
- 수치: 값, 단위, 조건, 비교 대상. 본문에서 단위를 바꾸거나 반올림할 값은 바꾼 값도 함께 적는다.
- 한계: 자료가 밝힌 한계와 실험 범위
- 용어: 원어와 이 글에서 쓸 표기
- 인용할 문장: 원문 그대로, 위치(쪽, 절)

### 3. 개요 잡기

- `references/style-guide.md`를 읽는다.
- 독자가 이 글을 읽고 알게 될 내용을 한 문장으로 정한다.
- 제목, 도입 방식, H2 섹션 4~7개, 섹션마다 쓸 fact sheet 항목을 정한다.

### 4. Default 초안 쓰기

Casual로 요청받아도 먼저 합니다체로 쓴다. Casual이면 `<이름>.draft.md`에, Default면 출력 파일에 바로 쓴다.

- 자료에 있는 사실만 쓴다. 자료에 없는 수치, 사례, 출처, 전망을 만들지 않는다.
- 자료를 주어로 쓴다: "저자들은 ~를 측정했습니다", "이 논문은 ~를 제안합니다". 자료를 "제공된 자료", "주어진 글"로 부르지 않는다. 직접 해 본 것처럼 쓰지 않는다.
- 주장은 바로 쓴다. 아무도 하지 않은 주장을 먼저 부정한 뒤 고쳐 말하지 않는다.
- 평가어 대신 자료의 수치와 이름을 쓴다. 중요하다고 말하는 대신 왜 중요한지(비용, 수치, 실패 조건)를 쓴다.
- 기본 동사(이다, 있다, 쓰다, 늘다, 줄다, 보다, 바꾸다)를 쓴다.
- 문장 길이를 섞는다. 조건과 결과를 한 문장에 담는 긴 문장도 둔다.
- 문단은 그 문단의 마지막 사실로 끝낸다. 요약이나 교훈 문장을 덧붙이지 않는다.
- 이유와 과정은 문단으로 쓴다. 목록은 단계, 설정값, 병렬 항목일 때만 쓰고 본문의 15%를 넘기지 않는다. "**라벨**: 설명" 목록을 이어 쓰지 않는다. bold는 핵심 수치나 용어에만, 한 문단에 하나 이하로 쓴다.
- 나열은 자료에 있는 항목 수 그대로 쓴다. 셋으로 맞추지 않는다.
- 쉼표는 문장을 끊어 읽어야 할 때만 쓴다. 연결어미(~고, ~며, ~지만, ~는데) 뒤와 문장 첫머리 접속부사(그리고, 하지만, 그래서, 따라서) 뒤에는 쓰지 않는다.
- 헤딩은 명사구, "~하기", "~할까" 질문으로 쓴다. 합니다체·해요체 종결을 헤딩에 쓰지 않는다.
- "~하는 바입니다", "~하고자 합니다" 같은 합니다체 전용 관용구를 쓰지 않는다.
- 용어: 한글 표기가 굳어진 외래어는 한글(서버, 캐시), 그 외는 영어 원문(race condition, latency). 번역어를 만들지 않는다.
- 마지막에 "참고자료" 섹션을 둔다.

이 단계에서는 `references/ai-patterns.md`를 읽지 않는다. 피할 표현 목록을 미리 보면 그 표현이 오히려 늘어날 수 있다.

### 5. 점검하고 고치기

1. 문체 검사를 실행한다(`--tone default`, `--facts`).
2. 결과의 GATE와 FAIL 항목은 반드시 고친다. WARN 항목은 deletion test로 지울 수 있는 문장이면 고치고, 아니면 둔다(WARN 3개까지는 통과다).
   - `references/ai-patterns.md`에서 그 항목을 고치는 방법을 찾는다.
   - 걸린 문장마다 deletion test를 한다. 그 구절을 지워도 정보(사실, 수치, 동작 원리)가 줄지 않으면 지운다. 정보가 있으면 그 정보를 직접 쓰는 문장으로 바꾼다.
   - 같은 수사 동작의 다른 표현으로 바꾸지 않는다("단순히 X가 아니라 Y"를 "X를 넘어 Y"로 바꾸는 식).
   - 수치, 고유명사, 인용은 바꾸지 않는다. 자료가 추정한 내용을 단정으로 바꾸지 않는다.
   - 기준치 안으로 들어오면 멈춘다. 사람 글에도 있는 표현까지 0으로 만들지 않는다.
   - Edit 도구로 걸린 문장만 바꾼다.
3. 다시 검사한다. 판정이 PASS가 될 때까지 반복한다(최대 3회). 고친 뒤 다른 항목 수치가 늘었으면 그 수정을 다르게 고친다. `--all`을 붙이면 참고 지표(INFO)까지 볼 수 있다.
4. `references/rubric.md`의 판정 항목 J1~J8로 글을 직접 읽고 점검한다. 특히 J1(자료의 문제·방법·결과·한계가 다 있는가), J3(지워도 되는 문장이 없는가), J5(한국 개발자가 쓴 글처럼 읽히는가)를 본다.

### 6. 어투 적용 (Casual일 때, `--retone`일 때)

1. `references/tone.md`를 읽는다.
2. 초안의 문장마다 종결부(마지막 1~2 어절)만 바꿔 출력 파일에 쓴다. 문장을 나누거나 합치지 않는다. 헤딩, 코드, 표, 인용, 명사구 목록은 그대로 둔다.
3. 어투 검사를 실행한다. 인자 순서는 항상 Default 글, Casual 글이다. FAIL이 나온 문장은 종결부만 다시 고친다.
4. 출력 파일에 문체 검사를 `--tone casual`로 실행한다. 종결어미 항목(G4, T.*)은 출력 파일에서 고친다. 그 밖의 항목이 걸리면 초안의 해당 문장을 고치고 다시 변환한다.
- `--retone`이면 입력 파일이 초안이다. Casual 글을 Default로 바꿀 때도 같은 대응표를 반대로 쓰고, 어투 검사의 인자 순서는 Default 글, Casual 글로 둔다.

### 7. 정리하고 보고하기

- `--keep-work`가 없으면 작업 파일 삭제 명령을 실행한다.
- 짧게 보고한다: 저장 경로, 어투, 본문 글자 수, 문체 검사 판정(Gate·FAIL·WARN 수), 어투 검사 결과(Casual일 때), 사용한 자료. 글 본문을 대화에 다시 붙이지 않는다.
