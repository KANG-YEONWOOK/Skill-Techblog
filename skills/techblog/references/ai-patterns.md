# AI 문체 패턴과 고치는 방법

초안을 쓴 뒤 점검 단계에서만 읽는다. 초안을 쓰기 전에 이 목록을 보면 목록의 표현이 오히려 늘어날 수 있다(Antislop 논문이 지적한 금지어 지시의 역효과).

각 항목의 ID는 `scripts/lint_ko.py` 결과와 `rubric.md`의 ID와 같다. 예시는 가상의 논문(김 등 2025, 캐시 무효화 지연 측정)을 정리하는 상황이다. 실제 자료의 사실이 아니므로 글에 옮기지 않는다. lint가 걸러 낸 문장만 고친다. 사람 글에도 있는 표현이라 기준치 안이면 그대로 둔다.

## 먼저 볼 항목

스킬 없이 Claude Opus 5.5가 쓴 기술 블로그 글 3편을 사람 글(토스, 카카오, 당근의 2022년 이전 글)과 비교했을 때 사람 글 p90을 넘은 항목이다. lint 결과에 이 항목이 있으면 먼저 고친다.

- 목록 비중(A9.list_ratio), "**라벨**: 설명" 목록(A9.label_list_ratio), bold(A9.bold_per_1k)
- 셋 묶음 나열(A10.triad_per_1k)
- 연결어미 뒤 쉼표(A2.connective_comma_ratio)
- 부정 대구(A1)

강조 문장, 과사용 어휘, Claude 번역 표현, 번역투는 사람 글 수준이었다. lint가 걸러 낸 경우에만 고친다.

영어 자료를 옮기며 생기는 문제는 따로 본다. 이 skill로 쓴 신경과학 학습 노트 14편은 lint에서 모두 PASS였지만, 사용자가 문장을 다시 읽고 고친 곳이 3주차 노트에서만 414곳이었다. 유형은 한 번 읽어서 뜻이 안 들어오는 문장 200곳, 영어 관용구와 동사의 직역 81곳, 그 분야에서 쓰지 않는 번역어 41곳, 그 밖의 번역투 40곳, 영어 낱말을 문장 성분으로 끼운 말 33곳, 예스럽거나 딱딱한 말 17곳, 범위를 "창"으로 쓴 말 2곳이다. 이 가운데 정규식으로 찾을 수 있는 형태만 lint가 센다(G6, G10, A5.archaic_words, A6.window_range, A6.calque_check, A14.quoted_english_token, A18.negation_scope, A19). 나머지는 6단계의 한국어 문장 점검([korean-review.md](korean-review.md))에서 문장마다 읽어서 찾는다. 아래 절의 사례 가운데 출처를 따로 밝히지 않은 실제 문장은 이 검토에서 나온 해요체 문장이다. 사례의 사실은 글에 옮기지 않는다.

## 고치는 절차

1. lint 결과에서 GATE, FAIL, WARN 항목의 문장을 본다.
2. 문장마다 deletion test를 한다. deletion test는 그 구절을 지웠을 때 글이 잃는 정보(사실, 수치, 동작 원리, 할 일)가 있는지 묻는 것이다.
   - 잃는 정보가 없으면 지운다.
   - 잃는 정보가 있으면 그 정보를 직접 쓰는 문장으로 바꾼다.
   - 주어, 목적어, 비교 기준, 수치가 가리키는 대상은 정보다. 앞 문장에 같은 말이 있어도, 지우면 그 문장만 읽고 뜻을 알 수 없게 되는 말은 지우지 않는다.
3. 같은 수사 동작의 다른 표현으로 바꾸지 않는다. 아래 "치환 금지"를 본다.
4. 수치, 고유명사, 인용은 바꾸지 않는다. 자료가 추정한 내용을 단정으로 바꾸지 않는다.
5. 다시 lint를 돌려 다른 항목이 늘지 않았는지 본다.

## 치환 금지

이 표현들은 모두 같은 동작이다. 하나를 지우고 같은 줄의 다른 표현을 넣으면 고친 것이 아니다.

| 동작 | 같은 동작의 표현들 |
|---|---|
| 부정하고 고쳐 말하기 | 단순히 X가 아니라 Y / X를 넘어 Y / X에 그치지 않고 Y / X라기보다 Y / 더 이상 X가 아닌 Y / X가 아닙니다. Y입니다. |
| 중요하다고 말하기 | 중요합니다 / 핵심입니다 / 주목할 만합니다 / 눈여겨볼 점은 / 기억해야 할 점은 / 왜 ~가 중요할까요 |
| 결론 표지 | 결론적으로 / 요약하자면 / 정리하면 / 요컨대 / 한마디로 / 결국 |
| 의미 부여 | ~를 시사합니다 / ~를 보여줍니다 / ~의 중요성을 일깨워 줍니다 / ~라는 점에서 의미가 있습니다 |
| 추상 은유 | 여정 / 지평 / 청사진 / 발판 / 토대 / 초석 / 떠받치다 |
| 추론 표지 | ~로 읽힙니다 / ~라고 읽을 수 있습니다 / ~다고 볼 수 있습니다 / ~로 해석할 수 있습니다 |

## 항목별

### A1, G8. 부정 대구
- 형태: "X가 아니라 Y", "단순한 X를 넘어 Y", "X라기보다 Y", "X에 그치지 않고 Y", "X가 아닙니다. Y입니다."
- 이유: 독자는 부정된 X를 먼저 처리한다. X는 대부분 아무도 주장하지 않은 내용이다. 한국어 실측에서 AI 글은 사람 글의 9.2배를 썼다.
- 고치는 법: X를 지우고 Y를 바로 쓴다. Y에 자료의 사실을 붙인다.
  - 전: 캐시 무효화는 단순한 삭제 작업이 아니라 분산 합의 문제입니다.
  - 후: 캐시 무효화 메시지는 12개 서비스의 캐시 노드에 모두 도착해야 끝납니다.
- 남기는 경우: 자료가 두 설정을 비교한 내용("배치 크기를 줄이면 지연은 줄었지만 쓰기 비율이 높은 서비스에서는 처리량이 15% 떨어졌습니다")은 대조가 정보다.

### A3. 강조 문장
- 형태: "이 점이 중요합니다.", "핵심은 ~입니다.", "주목할 점은", "왜 ~가 중요할까요?"
- 고치는 법: 강조 문장을 지운다. 왜 중요한지를 말해야 하면 그 이유(비용, 수치, 실패 조건)를 쓴다.
  - 전: 배치 크기 설정이 중요합니다. 설정에 따라 결과가 달라지기 때문입니다.
  - 후: 배치 크기를 100에서 10으로 줄이자 p99 지연이 4.2초에서 0.8초로 줄었습니다.

### A4, G9. 요약 표지, 문단 끝 교훈, 상투 도입과 마무리
- 형태: 문단 마지막의 "결국 ~", "이처럼 ~", "~를 보여줍니다", "~해야 합니다"(독자에게 하는 지시), 글머리의 "오늘날 ~는 빠르게 변화하고 있습니다", 글 끝의 "앞으로가 기대됩니다".
- 고치는 법: 문단 끝의 요약 문장과 교훈 문장은 지운다. 바로 앞 문장(마지막 사실)이 문단의 끝이 된다. 도입은 자료가 다루는 상황으로 바꾸고, 마무리는 결론이 성립하는 조건이나 자료가 밝힌 한계로 바꾼다.
  - 전: …p99 지연은 0.8초까지 내려갔습니다. 결국 작은 설정 하나가 사용자 경험을 좌우한다는 점을 보여줍니다.
  - 후: …p99 지연은 0.8초까지 내려갔습니다.

### A5. 과사용 어휘
- 형태: 시사하다, 구조적, 체계적, 통합적, 다층적, 핵심적, 실질적, 기능하다, 규명하다, 메커니즘, 기제, 추상 목적어를 받는 강화, 확대, 개선, 확보, 마련, 구축
- 고치는 법: 그 대상이 하는 일과 자료의 구체 표현으로 바꾼다.
  - 전: 이 결과는 배치 설계의 중요성을 시사합니다.
  - 후: 배치 크기를 10으로 줄인 설정에서 p99 지연이 0.8초로 가장 낮았습니다.
  - 전: 이 값은 기준으로 기능합니다. / 후: 저자들은 p99 무효화 지연 1초를 서비스 품질의 기준으로 삼습니다.
- 자료가 쓰는 용어(논문의 "mechanism"을 옮긴 "메커니즘")는 그대로 둔다.

### A5.archaic_words. 예스럽거나 딱딱한 말
- 형태: 관형사 "옛", "수치적으로 거의 0", "제시된", "전술한", "후술할", "~에 기인한", "무비판적으로"
- 이유: 사람 기술 블로그 글에는 거의 나오지 않는 말이다(측정은 저장소의 `dev/baseline/README.md`). 영어 자료의 old, numerically, presented, due to를 낱말 그대로 옮기면 생긴다.
- 고치는 법: 일상에서 쓰는 말로 쓴다.

| 쓴 말 | 고친 말 |
|---|---|
| 옛 진폭 값, 옛 출력 열 이름, 옛 주소 | 2020년 4월 neurolib이 저장한 `amp_x`, 예전 출력에 남은 열 이름, 예전 주소 |
| 수치적으로 거의 0 | 사실상 0 |
| 제시된 저항과 정전용량 | 논문에 나온 저항과 정전용량 |
| Results의 해당 설명 | 이 그림을 설명한 Results 부분 |
| 무비판적으로 옮기지 않은 | 그대로 옮기지 않은 |

- "해당 자료", "해당 설명"처럼 앞에서 말한 대상을 "해당"으로 다시 가리키는 말은 사람 글에도 흔해서 lint가 세지 않는다. 가리키는 대상이 바로 앞 문장에 없으면 대상의 이름을 쓴다. "~에 해당하다"(대응하다)는 고치지 않는다.

### A6. Claude 번역 표현과 상투 은유
- 형태: 떠받치다(load-bearing), 조용히(quietly), "두 축으로", "세 갈래로", "봐야 하는 자리", 여정, 지평, 청사진, 발판, 토대, 퍼즐 조각, 게임 체인저
- 고치는 법: 비유를 지우고 대상과 수치를 직접 쓴다.
  - 전: 메시지 큐가 전체 무효화 흐름을 떠받치고 있습니다.
  - 후: 무효화 메시지는 모두 하나의 큐를 거칩니다.
  - 전: 문제는 크게 두 축으로 나뉩니다. / 후: 무효화 지연은 메시지가 배치를 기다리는 시간과 노드 사이에 전파되는 시간에서 생깁니다.

### A6.window_range. 범위와 기간을 "창"으로 쓴 말
- 형태: "적분 창", "시간 창", "적분창", "20 ms 창", "고정 창"
- 이유: 영어 window를 "창"으로 옮기면 한국어 독자는 범위나 기간이라는 뜻을 바로 떠올리지 못한다. 사용자 검토에서 이 표현을 쓰지 않기로 정했다(policy). 1회부터 FAIL이다.
- 고치는 법: 범위, 기간, 한도는 기간, 구간, 범위, "~ 안에"로 쓴다. 자료가 이름처럼 쓰는 window(learning window, sliding window, context window, fixed window)는 영어 원문이나 한국어 개발 문서에서 굳은 음역(슬라이딩 윈도우)으로 쓰고, "범위"로 바꾸지 않는다. 화면의 창(검색창, 입력창, 브라우저 창)은 그대로 둔다.

| 쓴 표현 | 고친 표현 |
|---|---|
| 추정한 적분 창 길이 | 추정한 적분 기간 |
| STDP의 20 ms 시간 창 | STDP가 일어나는 spike 간격 범위 20 ms |
| 창이 열리고 닫히는 시각 | 기간이 시작하고 끝나는 시각 |
| TANGO의 적분창 | TANGO의 적분 기간 |

- "창이 열리고 닫히는", "윈도가 열리는 순간"처럼 열다, 닫다를 붙인 직역은 화면의 창("새 창을 열면")과 구분할 수 없어서 lint가 잡지 않는다. 읽어서 찾는다.

### A6.calque_check. 자료의 영어 동사를 그대로 옮긴 말
- 형태: 추상 명사(변화, 효과, 차이, 영향, 반응, 정보, 기능)에 붙은 "남다"(remain), "손으로 계산"(by hand). lint는 이 둘만 "한국어 점검 후보"로 보여 준다. 나머지는 읽어서 찾는다.
- 이유: 자료가 영어 논문이면 위의 Claude 번역 표현보다 자료의 동사를 낱말 그대로 옮긴 직역이 더 많이 나온다.
- 고치는 법: 무엇이 어떻게 됐는지를 한국어 동사로 쓴다.

| 원문 표현 | 직역 | 고친 문장 |
|---|---|---|
| remain | additive에는 큰 변화가 남아 있어요 | additive 실행에서는 영역 사이나 시간에 따라 값이 크게 달랐어요 |
| remain | 반응이 남았어요 | 반응이 사라지지 않았어요 |
| remain | neuromodulation도 남아요 | neuromodulation 정보도 따로 필요해요 |
| persist | hallucination이 남는 이유 | hallucination이 사라지지 않는 이유 |
| functionally silent | 기능적으로 조용할 수 있고 | 신호를 전하지 않다가 |
| recruit | 새 뉴런을 회로에 모집하거나 | 새 뉴런을 회로로 끌어들이거나 |
| support (states) | 같은 구조가 여러 상태를 지원할 수 있다 | 같은 구조에서 여러 상태가 나타날 수 있다 |
| had synapses onto | 근육에 시냅스를 내서 | 근육과 시냅스를 맺고 있어서 |
| by hand | FC를 손으로 다시 계산할 때는 | FC를 직접 다시 계산할 때는 |
| push into regions | softmax를 gradient가 아주 작은 영역으로 밀어낸다 | softmax의 gradient가 아주 작아진다 |
| offer | 질환을 이해하는 데 무엇을 줄 수 있을까요? | 질환을 이해하는 데 어떤 도움이 될까요? |
| perturb | 회로를 흔들어 보면 | 온도나 전류 조건을 바꾸면 |
| this understanding creates a problem | 이 이해가 배선도에 두 가지 문제를 만든다 | 신경계가 이렇게 작동한다면 배선도에는 두 가지 문제가 있다 |
| numerically | 수치적으로 거의 0이에요 | 사실상 0이에요 |
| low distance | 거리가 낮은 시점 쌍은 연결 패턴이 비슷합니다 | 거리가 가까운 시점 쌍은 연결 패턴이 비슷합니다 |
| amplitude fluctuations flattened | EEG 유사 신호의 진폭 변화가 평평해졌고 | EEG 유사 신호의 진폭이 거의 변하지 않았고 |

- 마지막 두 행은 0.6.0 시험 실행의 글에서 6단계 한국어 문장 점검을 거친 뒤에도 남은 문장이다. 영어 high, low를 늘 "높다, 낮다"로 옮기면 거리(가깝다, 멀다)처럼 다른 형용사를 쓰는 명사와 어긋난다.
- 그대로 두는 경우: 기록, 출력, 저장한 값처럼 실제로 남아 있는 대상("notebook에 출력이 남아 있다", "값에 입력이 남아 있다")과 굳은 말("문제가 남다", "할 일이 남다", "가능성이 남다")이다.

### A7. 추정 표현 중첩
- 형태: "~할 수 있을 것으로 보입니다", "~일 가능성이 있을 수 있습니다"
- 고치는 법: 자료의 추정 강도를 한 번만 쓰고, 누가 추정했는지 밝힌다.
  - 전: 다른 캐시 구조에서도 효과가 있을 수 있을 것으로 보입니다.
  - 후: 저자들은 write-through 캐시에서는 실험하지 않았습니다.
- A7.must_may: "~해야 할 수 있습니다"는 영어 "may need to"를 옮긴 표현이다. 사람 글 baseline 224편 중 2편에만 나왔다. 조건을 문장 앞에 쓰고 단정하거나, 필요성만 추정한다.
  - 전: 다른 캐시 구조에 적용하려면 배치 크기를 다시 정해야 할 수 있습니다.
  - 후: write-through 캐시에 적용한다면 배치 크기별 지연을 다시 측정해야 합니다. 논문의 측정은 write-back 캐시에서만 했습니다.
  - 후: 쓰기 비율이 높은 서비스에서는 배치 크기 조정이 필요할 수 있습니다.
- A7.read_as: "~로 읽힙니다", "~라고 읽을 수 있습니다"는 영어 "can be read as"를 옮긴 추론 표지다. 사람 글 baseline 224편 중 2편에만 나왔다. 근거를 조건으로 앞에 쓰고 결론을 쓰거나, 자료가 직접 말하지 않은 해석이면 "~일 수 있습니다"로 한 번만 추정한다.
  - 전: 표에서 지연 대부분이 배치 대기에서 생긴다고 읽을 수 있습니다.
  - 후: 표의 측정값대로라면 지연의 72%는 배치 대기에서 생깁니다.
- A7.see_as: "~다고 볼 수 있습니다"도 A7.read_as와 같은 추론 표지다. "~로 읽힙니다"를 이 표현으로 바꾸는 것은 고친 것이 아니다. 사람 글 224편에서는 1만 자당 0.14회 나왔다. 고치는 방법은 A7.read_as와 같다. 저자가 한 해석이면 연구 이름을 주어로, 그 일에 맞는 동사(추정합니다, 해석합니다)로 옮긴다.
  - 전: 이 결과로 보아 지연을 줄인 것은 배치 크기라고 볼 수 있습니다.
  - 후: 배치 크기만 100에서 10으로 바꾼 실험에서 p99 지연은 4.2초에서 0.8초로 줄었습니다.

### G7, A2. 쉼표
- 형태: "그리고,", "하지만,", "따라서," / 연결어미 뒤 쉼표("적용했지만, 줄지 않았습니다")
- 고치는 법: 접속부사 뒤 쉼표는 지운다. 연결어미 뒤 쉼표는 문장이 길어 끊어 읽어야 할 때만 남긴다.
  - 전: 그리고, 저자들은 로그를 모았고, 지연을 측정했습니다.
  - 후: 그리고 저자들은 로그를 모아 지연을 측정했습니다.

### G6. 문장 부호: 가운뎃점, em dash, en dash, 빼기 기호
- 형태: 가운뎃점(·), em dash(—), en dash(–), 빼기 기호(−), 줄표 대신 띄어 쓴 하이픈(" - ")이다. 본문, 제목, 헤딩, 표, 인용, 그림 설명 모두 센다. 코드 블록, 인라인 코드, 수식, URL은 뺀다. 참고자료 절에서는 쪽 범위의 대시만 센다.
- 이유: 사용자 검토에서 쓰지 않기로 정한 정책이다(G6.emdash, G6.punct_policy). 사람 블로그에도 가운뎃점은 나오지만(1,000자당 0.125개) 이 skill의 글에는 쓰지 않는다.
- 고치는 법: 쓰임을 먼저 나눈다. 쓰임마다 바꾸는 방법이 다르다.

| 쓰임 | 바꾸는 방법 | 전 → 후 |
|---|---|---|
| 여럿을 나열 | 쉼표 | PD·LP·PY 뉴런 → PD, LP, PY 뉴런 |
| 두 수식어가 한 명사를 함께 꾸밈 | "A와 B", "A나 B", "A인지 B인지"로 풀기 | 흥분·억제 sign → sign(흥분성인지 억제성인지) |
| 두 형용사가 한 명사를 꾸밈 | "A와 B"나 문장으로 풀기 | 낮은·높은 입력의 안정 상태 → 낮은 입력과 높은 입력에서 안정 상태 |
| 이름이나 쌍을 이음 | 하이픈 | Morris–Lecar 모델 → Morris-Lecar 모델, LP–PY 시냅스 → LP-PY 시냅스 |
| 수의 범위 | 물결표 | 12–24시간 → 12~24시간 |
| 음수 | 하이픈 | −52 mV → -52 mV |
| 낱말 사이의 빼기 | 풀어 쓰기 | 최대−최소 진동 폭 → 진동 폭(최댓값에서 최솟값을 뺀 값) |
| 라벨과 소제목의 구분자 | 콜론 | 1단계 — 설정 → 1단계: 설정 |
| 문장 안의 덧붙임 | 쉼표나 문장 분리 | 지연은 줄었다 — 처리량은 그대로였다 → 지연은 줄었고 처리량은 그대로였다 |
| 영어 인용문 안에서 삽입구를 묶은 em dash | 쉼표 한 쌍 | model—in which SC provided the exact coupling matrix—as in → model, in which SC provided the exact coupling matrix, as in |
| 표의 빈 칸 | "-"나 "없음" | — → - |
| 참고자료의 쪽 범위 | 하이픈 | pp. 1016–1054 → pp. 1016-1054 |

- 바꾸는 절차: 사용자 검토에서는 노트 14편의 가운뎃점 297개, em dash 3개, en dash 320개, 빼기 기호 13개를 스크립트로 한꺼번에 바꿨고, 그 뒤 아래 문제가 남아 문장을 다시 읽으며 고쳤다.

| 치환 결과 | 문제 | 고친 문장 |
|---|---|---|
| 생리적, 생화학적 뉴런 subtype | 독자가 "생리적"을 따로 된 항목으로 읽는다. 원문은 physiological and biochemical neural subtypes | 생리 특성과 생화학 특성으로 구분한 뉴런 subtype |
| 흥분, 억제 sign | 두 항목을 나열한 것처럼 읽힌다 | sign(흥분성인지 억제성인지) |
| neuromodulators-biogenic amines | em dash가 하이픈이 되면서 영어 인용문에 없는 합성어가 생겼다 | neuromodulators, biogenic amines |
| computational mode-in which ... matrix-as in | 같은 이유로 "mode-in", "matrix-as"라는 낱말이 생겼다 | computational mode, in which ... matrix, as in |

  1. 걸린 곳마다 그 문자의 쓰임을 위 표의 행으로 먼저 나눈다. 편집 도구의 전체 바꾸기(replace_all), sed, PowerShell `-replace` 같은 일괄 치환은 쓰지 않는다. 가운뎃점을 빗금(/)으로 바꾸는 것도 같은 수사 동작이라 고친 것이 아니다.
  2. 수식어의 짝과 낱말 사이의 빼기는 쉼표나 하이픈으로 바꾸지 않고 문장을 다시 쓴다.
  3. 영어 인용문 안의 em dash는 쉼표 한 쌍으로 바꾸고 하이픈으로 바꾸지 않는다. "인용은 바꾸지 않는다"는 원칙의 예외다. 인용문의 뜻은 그대로다.
  4. 바꾼 문장을 모두 다시 읽는다. lint는 나열과 짝이 섞인 쉼표를 잡지 못한다.

### G10. 숫자 뒤 조사
- 형태: 숫자, %, %p 바로 뒤의 조사가 숫자를 읽는 소리와 맞지 않는다. 사용자 검토에서 계산한 값 뒤에 조사를 고정해 붙인 출력이 "최댓값은 0.7717예요"(맞는 조사: 이에요), "diffusive에서 0.120예요"(이에요), "현재 표본의 상관은 0.512이에요"(예요)를 냈다.
- 이유: 맞춤법이다(policy). 어투를 바꾸면서 "~입니다"를 "~이에요/예요"로 바꿀 때 앞 글자가 숫자면 받침을 잘못 보기 쉽다.
- 고치는 법: 마지막 숫자를 읽는 소리로 조사를 고른다.
  - 받침이 있는 숫자: 0(영, 십, 백, 천, 만), 1(일), 3(삼), 6(육), 7(칠), 8(팔). 받침이 없는 숫자: 2(이), 4(사), 5(오), 9(구).
  - "으로/로": 받침이 ㄹ이면 "로"다. 1, 7, 8 뒤에는 "로", 0, 3, 6 뒤에는 "으로", 2, 4, 5, 9 뒤에는 "로"를 쓴다.
  - %는 "퍼센트"로 읽어 받침이 없다(15%예요, 15%를). 단위가 붙으면 단위를 읽는 소리로 정한다(0.8초예요, 120 ms예요, 3건이에요).
  - "였"은 받침 없는 소리 뒤에만 쓴다(0.512였습니다, 0.7717이었습니다).
- lint는 영문과 숫자로만 된 낱말 바로 뒤의 숫자(Llama 3, Windows 11)와 영문, 하이픈, 빗금, @ 바로 뒤의 숫자(GPT-3, v2, HTTP/3, corejs@3)를 영어로 읽는 이름으로 보고 건너뛴다. 영어 낱말과 단위 뒤의 조사는 lint가 보지 않는다. tone.md의 "숫자, 영어, 기호 뒤 조사" 규칙으로 고른다.

### A8. 문장 리듬
- 형태: 비슷한 길이의 짧은 문장이 이어진다. 같은 종결("~했습니다.")이 4번 이상 이어진다.
- 고치는 법: 원인과 결과, 조건과 결과를 한 문장으로 잇는다. 종결을 섞는다(~했습니다 / ~입니다 / ~수 있습니다 / ~있습니다).
  - 전: 저자들은 로그를 모았습니다. 로그는 3억 건입니다. 12개 서비스에서 모았습니다.
  - 후: 저자들은 12개 서비스에서 로그 3억 건을 모아 무효화 메시지가 발행된 시점부터 마지막 노드에 반영된 시점까지를 측정했습니다.
- A8.single_para_ratio: 한 문장 문단이 너무 적다. 사람 글은 문단당 평균 2문장이고 문단의 27~52%가 한 문장 문단이다. dogfooding에서 이 스킬의 출력은 문단당 3.0~3.5문장, 한 문장 문단 4~9%로 사람 글 66편의 최솟값(7.4%) 근처였다.
  - 고치는 법: 네 문장 이상인 문단에서 내용이 바뀌는 곳(새 사실, 새 수치, 원인에서 결과로 넘어가는 곳)을 찾아 문단을 나눈다. 문장은 바꾸지 않고 빈 줄만 넣는다. 한 가지 논증의 중간을 끊지 않는다. 정리 문장이나 예고 질문을 새로 써서 문단 수를 늘리지 않는다. dogfooding iteration 6에서 "절의 결론은 한 문장 문단으로 둔다"는 지시를 따르자 "연속 할당을 유지하면 길이를 완벽하게 예측해도 낭비가 남아요." 같은 한 줄 정리 문단이 생겼고 judge는 이를 요약 표지로 읽었다.
- A8.sent_len_cv: 문장 길이가 고르다. 사람 글에서 35자 미만인 문장은 문장의 12~25%(p25~p75)다. dogfooding iteration 9에서 문장마다 주어와 측정 대상을 쓰라는 규칙을 따른 글은 35자 미만인 문장이 2~12%로 줄었고, 문장 길이 변동계수가 0.36~0.43으로 사람 글 p25(0.44)보다 낮았다. style judge는 이 가운데 세 글에 "같은 문형이 길게 이어져 단조롭다"는 이유로 J8 1점을 줬다.
  - 고치는 법: 사실 하나만 전하는 문장을 짧게 쓴다. 주어를 지워서 문장을 짧게 만들지 않는다.
  - 전: 실험에 사용한 서비스는 모두 write-back 캐시를 사용하는 12개 서비스이며, 저자들은 이 서비스들에서 로그 3억 건을 모았습니다.
  - 후: 실험에는 write-back 캐시를 사용하는 12개 서비스를 선택했습니다. 모은 로그는 3억 건입니다.

### A9, A10. 서식과 셋 묶음
- 형태: 모든 항목이 "**라벨**: 설명"인 목록, 문단마다 bold, 근거 없이 셋으로 맞춘 나열("빠르고, 정확하고, 안정적입니다")
- 고치는 법: 이유와 과정은 문단으로 쓴다. bold는 핵심 수치나 용어 하나에만. 나열은 자료에 있는 항목 수 그대로 쓴다(둘이면 둘, 넷이면 넷).
  - 전: - **지연**: 낮음 / - **처리량**: 유지 / - **비용**: 감소
  - 후: 배치 크기를 10으로 줄인 설정은 p99 지연을 0.8초로 낮췄고, 쓰기 비율이 30% 미만인 서비스에서는 처리량이 줄지 않았습니다.

### A11. 질문
- 형태: 문장 중간이나 문단마다 스스로 묻고 답하는 질문("결과는? 놀라웠습니다")
- 고치는 법: 섹션을 여는 질문만 남긴다. 나머지는 답을 바로 쓴다.

### A13, A14. 지시어와 번역투
- 형태: "이는 ~를 의미합니다", "이러한 ~", "그것은", "~에 의해", "가장 ~한 ~ 중 하나", "중요한 역할을 합니다", "~를 가지고 있습니다"
- 고치는 법: 가리키는 대상을 이름으로 쓰고, 주어와 서술어를 한국어 어순으로 쓴다.
  - 전: 이는 배치 대기가 지연의 주요 원인임을 의미합니다.
  - 후: 지연의 72%가 배치 대기에서 생겼습니다.
  - 전: 메시지 큐는 중요한 역할을 합니다. / 후: 무효화 메시지는 모두 메시지 큐 하나를 거쳐 각 캐시 노드로 전달됩니다.
- lint가 세지 않는 번역투도 같은 방법으로 고친다. "~를 가질 수 있다"(can have), "~하게 되다"(come to), "~를 통한 회피"처럼 경로를 말하는 "~를 통해"는 한국어 동사로 쓴다.
  - 전: 이 설정은 더 낮은 지연을 가질 수 있습니다. / 후: 이 설정에서는 지연이 더 짧을 수 있습니다.
  - 전: chemical synapse를 통한 회피 / 후: chemical synapse를 거치는 회피
- "최댓값을 가진다", "큰 값을 가진다"는 수학에서 굳은 표현이라 고치지 않는다. 속성의 "~를 가지고 있다"(A14)와 다르다.

### A14.quoted_english_token, A14.quoted_english_check. 따옴표 친 영어 낱말을 문장 성분으로 쓴 말
- 형태: `"likely"로 쓴 추정`, `"over"로 적은 하한`, `"suggest"로 쓴 추정`(FAIL), `"overconnected"로 보일 것`, `"etc."로 끝나므로`(한국어 점검 후보)
- 이유: 자료의 추정 강도와 표현을 지키라는 규칙을 영어 낱말을 그대로 옮기는 것으로 따르면 생긴다. 독자는 문장 안에서 영어 낱말의 뜻을 다시 옮겨 읽어야 한다. "쓰다, 적다, 표현하다, 추정하다"가 붙으면 자료의 낱말을 옮긴 것이 분명해서 FAIL이다. "끝나다, 보이다"가 붙으면 로그나 화면에 찍힌 값일 수 있어서 점검 후보다.
- 고치는 법: 뜻을 한국어로 먼저 쓰고 영어 원문은 괄호나 각주에 둔다. 추정 표현은 style-guide.md의 추정 표현 대응표로 옮긴다. 코드, 상태 값, 화면에 찍힌 값이면 인라인 코드로 쓴다.

| 쓴 문장 | 고친 문장 |
|---|---|
| Inagaki 2012가 "likely"로 쓴 추정 적분 창 12~24시간 | Inagaki 2012가 추정한 적분 기간 12~24시간(처음 12~24시간의 신호가 반영됐을 가능성이 높다는 저자들의 추정) |
| retrovesicular ganglion 뉴런 13개는 "suggest"로 쓴 추정이라 | retrovesicular ganglion 뉴런 13개의 상동 관계는 저자들이 추정한(suggest) 것이라 |
| "over"로 적은 neuropeptide 수의 하한이다 | neuropeptide가 그 수보다 많다는 뜻의 하한이다 |
| 원문의 목록이 "etc."로 끝나므로 | 원문은 여섯 항목 뒤에 "등"(etc.)을 붙였으므로 |
| 뉴런이 "overconnected"로 보일 것 | 뉴런이 과하게 연결된(overconnected) 것처럼 보일 것 |
| "slow" modulatory 반응 | 느린(slow) modulatory 반응 |

- lint가 잡지 못하는 형태: 마지막 두 행처럼 따옴표 안 영어를 수식어나 서술어로 쓴 문장, 인라인 코드로 감싼 영어 낱말(`` `likely`로 쓴 ``)이다. 읽어서 찾는다.
- 그대로 두는 경우: 영어 문장을 통째로 인용한 근거(`원문은 "..."입니다`), 논문이 붙인 이름을 고유명처럼 쓴 경우(`저자들은 이를 "the three S's"라고 부릅니다`)다.

### A14.report_write, A14.report_write_check. 자료의 말을 옮기는 동사
- 형태: 따옴표나 "~다고", "~라고" 뒤의 "쓰다", "적다"(A14.report_write, FAIL. "~고 써요", "~라고 썼습니다", "~다고 쓰고"), 같은 자리의 관형형("~고 쓴 추정", "~라고 적은 값", 한국어 점검 후보 A14.report_write_check)
- 이유: 영어 "the authors write"를 옮긴 "쓰다"는 자료가 주장했는지, 보고했는지, 추정했는지를 드러내지 않는다. 현재형 "써요"는 저자들이 지금 쓰고 있는 것처럼 읽힌다. "쓰다"는 '사용하다'로도 읽혀서 같은 글의 "이 방법을 사람 뇌에 썼어요"와 섞인다. 사용자 검토 노트 14편 중 13편에 이 형태가 있었고 사람 글 224편에는 한 번도 없었다. 따옴표로 옮긴 말 뒤의 조사는 "라고"와 "고"를 모두 쓴다. 0.8.0은 따옴표 뒤의 "고"를 FAIL로 셌지만(A14.quote_go), 사람 글 224편 중 19편이 쓰는 형태이고 사용자도 자연스러운 말로 본다(2026-10-18). 0.9.0에서 이 항목을 뺐다.
- 고치는 법: 자료가 그 문장에서 하는 일에 맞는 동사로 쓰고, 자료의 강도를 지킨다(style-guide.md의 "자료의 말을 옮기는 문장"). 여러 연구를 인용한 글이면 연구 이름도 쓴다. 표나 로그에 실제로 남은 기록은 "~라고 적혀 있습니다"로 쓴다.

### A18. 앞 문장에 기대야 뜻이 통하는 문장과 압축 표현
- 이 항목은 판정(PASS, WARN, FAIL)에 들어가지 않는다. lint는 아래 두 형태에 걸린 문장을 "단독 읽기 점검 후보"로 보여 주고, 5단계의 단독 읽기 점검에서 이 문장들을 먼저 읽는다.
  - A18.number_predicate: 수치로 끝나는 짧은 문장. 무엇을 잰 값인지가 빠지기 쉽다("최대 5배입니다."). 이 형태는 사람 글보다 스킬 글에 1,000자당 100배 넘게 많이 나왔다.
  - A18.bare_reference: "둘을", "차이는", "그 값은", "그 결과"로 시작하는 문장. 가리키는 대상이 앞 문단에 있으면 그 문장만 읽고 뜻을 알 수 없다. 이 형태는 사람 글보다 스킬 글에 1,000자당 약 4배 많이 나왔다.
  - A18.bare_author: 본문이 연구를 둘 이상 인용하는데 "저자들은", "세 저자는", "같은 논문은"처럼 어느 연구인지 밝히지 않은 주어가 있고, 그 문장과 바로 앞 문장에 연구 이름이 없는 문장. 사용자 검토 노트 14편 중 6편에서 14곳이 걸렸고 사람 글 224편에서는 1편이었다. 연구 이름을 쓴다(style-guide.md의 "자료의 말을 옮기는 문장").
- 아래 세 형태는 사람 글에도 스킬 글과 비슷한 비율로 나와서 참고 지표(INFO)로만 센다. lint에 `--all`을 붙이면 걸린 문장을 볼 수 있다.
  - A18.generic_predicate: "~경우입니다", "~결과입니다", "~방법입니다", "~방식입니다"로 끝나는 짧은 문장. 무엇이 그 경우나 결과인지 주어가 빠지기 쉽다.
  - A18.paren_clause: 괄호 안에 조건이나 설명을 절로 끼워 넣은 문장.
  - A18.bundle: 명사를 빗금(/)이나 가운뎃점(·)으로 묶은 문장. 가운뎃점은 G6.punct_policy가 Gate로 센다.
- A18.negation_scope는 "한국어 점검 후보"로 보여 준다. "모든 X가 ~지 않았다", "X가 모두 ~지 않았다"는 "어느 X도 ~지 않았다"(전부 부정)로도, "X가 모두 ~한 것은 아니다"(일부 부정)로도 읽힌다. 자료가 뜻한 쪽으로 쓴다.
  - 전: 모든 영역이 한 값에 머물지 않았습니다.
  - 후(일부 부정): 80개 영역이 모두 한 값에 머문 상태는 아니었습니다.
  - 후(전부 부정): 80개 영역 가운데 어느 영역도 한 값에 머물지 않았습니다.
- 멈춤 기준: 걸린 문장과 바로 앞 문장만 읽고 무엇에 대한 말인지, 수치가 무엇을 잰 값인지 답할 수 있으면 그대로 둔다.
- 고치는 법: 빠진 주어, 측정 대상, 비교 기준을 fact sheet에서 찾아 그 문장에 넣는다. 바로 앞 문장과 주어가 같아서 주어를 뺀 문장은 그대로 둔다. 괄호 안의 조건과 설명하는 절은 괄호 밖에 문장으로 쓴다. 한 구절짜리 용어 설명은 괄호에 둔다.
  - 전: 배치 크기를 100에서 10으로 줄였습니다. p99 기준 0.8초입니다.
  - 후: 무효화 메시지의 배치 크기를 100에서 10으로 줄이자 p99 무효화 지연이 4.2초에서 0.8초로 줄었습니다.
  - 전(새 문단의 첫 문장): 차이는 쓰기 비율에서 갈립니다.
  - 후: 배치 크기를 10으로 줄인 설정은 쓰기 비율이 30%를 넘는 서비스에서 처리량을 15% 떨어뜨렸습니다.
  - 전: 12개 서비스·로그 3억 건(write-back 캐시만 해당) 기준으로 측정한 결과입니다.
  - 후: 지연은 write-back 캐시를 사용하는 12개 서비스의 로그 3억 건으로 측정했습니다.
  - 전: 어투는 Default와 Casual 중에서 선택합니다. 어투만 바뀌고 내용은 같습니다.
  - 후: 이 skill로 글을 쓸 때 글의 어투를 Default(합니다체)와 Casual(해요체) 중에서 선택할 수 있습니다. 두 어투로 쓴 글의 내용은 같습니다.
- 과교정 1: 같은 주어를 문장마다 되풀이하면 글이 늘어지고 J8(과교정) 판정에서 감점된다. 같은 대상을 설명하는 문장이 이어지면 첫 문장에만 주어를 쓴다.
  - 과교정: 배치 크기를 10으로 줄인 설정은 p99 지연을 0.8초로 낮췄습니다. 배치 크기를 10으로 줄인 설정은 쓰기 비율이 30%를 넘는 서비스에서 처리량을 15% 떨어뜨렸습니다.
  - 적정: 배치 크기를 10으로 줄인 설정은 p99 지연을 0.8초로 낮췄습니다. 쓰기 비율이 30%를 넘는 서비스에서는 처리량을 15% 떨어뜨렸습니다.
- 과교정 2: 주어를 한 번만 쓰려고 서로 다른 사실 여러 개를 "~고", "~며"로 한 문장에 이으면 문장이 길어져 읽기 어렵다. dogfooding iteration 8에서 문장을 이으라는 지시를 따른 PagedAttention 글은 평균 문장 길이가 63.9자에서 78.8자로 늘었고, pairwise judge는 "~고 ~며"로 이어 붙인 긴 문장을 지적했다.
  - 과교정: 배치 크기를 10으로 줄인 설정은 p99 지연을 0.8초로 낮췄고 쓰기 비율이 30% 미만인 서비스에서는 처리량이 그대로였으며 쓰기 비율이 30%를 넘는 서비스에서는 처리량을 15% 떨어뜨렸습니다.
  - 적정: 배치 크기를 10으로 줄인 설정은 p99 지연을 0.8초로 낮췄습니다. 쓰기 비율이 30% 미만인 서비스에서는 처리량이 줄지 않았습니다. 쓰기 비율이 30%를 넘는 서비스에서는 처리량이 15% 떨어졌습니다.
- 과교정 3: 빠진 주어를 "논문은", "원문은", "저자들은"으로 채우면 글이 자료를 요약한 보고서처럼 읽힌다. 자료가 잰 값과 자료가 설명한 동작은 그 값과 동작을 주어로 쓴다. lint의 A16이 이런 문장의 비율을 센다.
  - 과교정: 논문은 배치 크기를 10으로 줄인 설정에서 p99 지연이 0.8초였다고 보고합니다.
  - 적정: 배치 크기를 10으로 줄인 설정에서 p99 무효화 지연은 0.8초였습니다.

### A19. 한 개념을 두 표기로 쓴 곳
- 형태: 병기한 쌍(`망막(retina)`, `retina(망막)`)의 두 표기를 병기한 곳 밖에서 섞어 쓴다(A19.term_mix). fact sheet 용어 표에서 쓰지 않기로 한 표기를 쓴다(A19.term_avoid). 둘 다 "한국어 점검 후보"로 보여 준다.
- 이유: 독자는 다른 표기를 다른 대상으로 읽는다. 여러 agent가 글을 나눠 쓰거나 고치면 한 개념이 두 표기로 갈린다. 사용자 검토에서 한 노트는 제목을 "retina와 큰 회로의 connectome"으로 쓰고 본문은 첫 등장의 "retina(망막)" 뒤로 "망막"을 39번 썼다. 다른 노트는 표기 결정이 "시뮬레이션한 FC"인데 "시뮬레이션 FC"를 섞어 썼다.
- 고치는 법: fact sheet 용어 표의 "글에 쓸 표기"로 맞춘다. 병기는 처음 나올 때 한 번만 쓴다. 제목, 헤딩, 표, 그림 설명도 같은 표기로 쓴다.
- 그대로 두는 경우: 다른 개념의 합성어("흥분성 뉴런"은 excitability와 다른 개념이다), 약어 정의 뒤의 약어(다중 버전 동시성 제어(MVCC) 뒤의 MVCC)다.
- lint는 병기한 쌍만 본다. "시뮬레이션한 FC"와 "시뮬레이션 FC"처럼 병기 없이 갈린 표기는 읽어서 찾는다. 이 검사는 사용자 검토 노트에서 사용자가 고치지 않고 둔 쌍도 많이 잡았다(측정은 `dev/baseline/README.md`). 같은 개념을 두 표기로 쓴 것이 아니면 그대로 둔다.

### A20. 처음 나오는 용어의 설명
- 이 항목은 판정에 들어가지 않는다. lint는 아래 여섯 형태를 "용어 설명 점검 후보"로 보여 준다.
  - A20.term_first: fact sheet 용어 표의 "처음 나올 때 설명" 열에 설명을 적은 용어가 본문에 처음 나온 문장(`--facts`를 줄 때). 같은 문장에 처음 나온 용어는 한 줄로 묶고, 앞의 몇 곳 뒤로는 "나머지 N곳"에 줄 번호와 용어를 모두 보여 준다. 0.8.0은 앞의 5곳만 보여 줘서 뒤 절의 pyloric 리듬과 amacrine 세포가 점검 목록에 오르지 않았다.
  - A20.term_in_list: 여럿을 쉼표로 나열한 문장에서 처음 나왔고, 바로 다음 문장에 다시 나오지 않으며, 뒤에서 나열 밖에 혼자 다시 나오는 용어. 꾸미는 말("신호를 전달하는 interneuron")이 붙은 항목은 그 자리에서 설명한 것으로 본다. 쉼표가 하나인 "A, B와 C" 나열은 보지 않는다.
  - A20.untabled: 본문에 두 번 이상 나오는데 용어 표의 원어, 글에 쓸 표기, 쓰지 않을 표기 어디에도 없는 영어 낱말(`--facts`를 줄 때). 저자(연도) 인용, 학명, 대문자 약어, 사람과 기관 이름처럼 모든 낱말이 대문자로 시작하는 구간은 뺀다.
  - A20.table_combined_row: 용어 표에서 용어 여러 개를 한 행에 묶은 곳(`--facts`를 줄 때). 줄 번호 대신 "fact sheet"로 표시한다.
  - A20.species_first: "C. elegans", "D. melanogaster" 같은 학명과 기울임꼴 학명이 처음 나온 문장
  - A20.abbr_first: 본문에 세 번 이상 나오고 용어 표에 없는 대문자 약어가 처음 나온 문장 가운데 괄호가 없는 문장. TV, PC, USB처럼 일상에서 쓰는 약어와 SQL, HTTP 키워드(SELECT, GET)는 세지 않는다. API, CPU 같은 분야 약어는 0.9.0부터 센다.
- 이유: 분야 밖 독자는 처음 나온 말이 무엇인지 모르면 그 뒤 문장을 따라가지 못한다. 사용자 검토에서 노트 14편 중 어느 편도 C. elegans가 무엇인지 쓰지 않았고, 7편은 STG를 "위를 움직이는 신경절"처럼 이름만 옮겼다. lint는 괄호가 있는지만 볼 수 있어서, 학명과 용어 표의 용어는 괄호가 있어도 첫 문장을 보여 준다.
- 멈춤 기준: 걸린 문장이나 바로 다음 문장에 그 말이 무엇인지(상위 범주와 구별되는 특징), 무엇을 하는 대상이면 무엇을 하는지, 원어로 둔 이름이면 이름의 뜻을 쓴 설명이 있으면 그대로 둔다. 일상 한국어처럼 자료 분야를 모르는 독자도 아는 말이면 그대로 둔다.
- 고치는 법: style-guide.md의 "처음 나오는 용어와 중심 대상 설명"대로 쓴다. 설명에 쓰는 사실은 fact sheet 용어 표에서 가져오고, 표에 없으면 자료, 그다음 일반 지식(사전, 교과서, 백과사전) 순서로 찾아 용어 표에 근거와 함께 더한다.

| 쓴 문장 | 고친 문장 |
|---|---|
| C. elegans라는 선충의 성체 자웅동체(hermaphrodite) 신경계에는 뉴런이 302개 있어요. | C. elegans(예쁜꼬마선충)는 흙에 사는 아주 작은 벌레(선충)의 한 종이에요. 성체 자웅동체(hermaphrodite)의 신경계에는 뉴런이 302개 있어요. |
| 게 Cancer borealis의 STG(stomatogastric ganglion, 위를 움직이는 신경절)이에요. | 게 Cancer borealis의 STG(stomatogastric ganglion)예요. STG는 게의 위를 움직이는 신경계에 있는 신경절(뉴런의 세포체가 모인 덩어리)이고, 그 안의 뉴런 약 27개가 위의 근육을 리듬에 맞춰 움직이는 신호를 만들어요. |

- 위 두 행은 2026-10-18 사용자 검토에서 지적한 노트 문장이다. 고친 문장은 이 기준으로 다시 쓴 예이고, 사례의 사실은 글에 옮기지 않는다.

### A21.sseuda_senses. 한 글에서 두 뜻으로 쓴 "쓰다"
- 형태: 한 글에 "쓰다"를 '사용하다'로 쓴 문장(목적어가 붙은 "~를 썼어요", "쓸 수 있어요")과 자료의 말을 옮기는 데 쓴 문장(인용 동사 패턴에 걸리거나 저자(연도)가 있는 문장의 "쓰다")이 함께 있다. 판정에 들어가지 않는 한국어 점검 후보다.
- 이유: 독자는 같은 낱말을 같은 뜻으로 읽는다. 사용자 검토 노트 14편 중 13편이 "쓰다"를 두 뜻으로 함께 썼고, 사람 글 224편에서는 한 편도 없었다. 이런 노트에서 "이 방법을 사람 뇌에 썼어요"는 '논문에 적었다'로 먼저 읽힌다.
- 고치는 법: '사용하다' 뜻으로 쓴 "쓰다"는 "사용하다"로 쓴다(style-guide.md의 "정보 전달 글의 동사"). 자료의 말을 옮긴 문장은 그 말이 하는 일에 맞는 동사로, '기록하다', '나타내다' 뜻으로 쓴 곳은 그 뜻의 말("0으로 표시해요", "두 변수로 나타낸 모델")로 쓴다. 보다, 적다, 나오다, 두다는 lint가 세지 않는다. 6단계의 한국어 문장 점검이 유형 M으로 읽어서 찾는다.

### A14.doeeojida, G11.spelling. 이중 피동과 맞춤법
- 형태: "~되어지다", "보여지다", "쓰여지다", "나뉘어지다", "잊혀지다"처럼 피동을 두 번 표시한 말(A14.doeeojida, FAIL). "되요", "됬", "몇일", "금새", "일일히", "왠만", "웬지", "가르키다", "역활", "오랫만", "~ㄹ께"(G11.spelling, Gate)
- 이유: 규범에 어긋난 말이다. 사람 글 218편에서 이중 피동은 9편, 맞춤법 오류는 5편에 있었고 걸린 문장은 모두 실제 오류였다. 사람 글에도 있는 형태라 이 skill의 출력에만 적용하는 policy 항목으로 둔다.
- 고치는 법: 피동은 한 번만 쓴다(보인다, 쓰인, 나뉜다). 맞춤법은 hint의 바른 말로 쓴다(돼요, 됐다, 며칠, 금세, 일일이, 웬만, 왠지, 가리키다, 역할, 오랜만, ~ㄹ게).
- 그대로 두는 경우: 따옴표로 인용한 원문, 로그, 코드다. lint는 따옴표 안과 인라인 코드를 세지 않는다.

### A14.causative, A5.pleonasm, A14.adverb_pair, A21.jeokda_as. 한국어 점검 후보 (0.9.0)
- 형태
  - A14.causative: "~하다"로 써도 뜻이 같은 "~시키다"(소개, 연결, 포함, 유지, 통합, 전환, 적용, 입력, 반영, 교육, 주입, 접목, 결합, 대입 + 시키다)
  - A5.pleonasm: 같은 뜻을 두 번 쓴 말(약 N 정도, 다시 재시작, 미리 예측, 과반수 이상, 가장 최선)
  - A14.adverb_pair: 짝이 없는 부사(부정이 없는 "결코", 양보 어미가 없는 "비록", "때문"이 없는 "왜냐하면", 조건 어미가 없는 "만약")
  - A21.jeokda_as: "X를 Y로 적다". 글에서 부를 이름을 정하는 '부르다'의 뜻이나 자료가 밝힌 값을 옮기는 뜻으로 쓴 "적다"다. 3주차 노트 14편 중 7편에서 18곳이 걸렸다.
- 이유: 사람 글에도 있는 형태라 판정에 넣지 않고 다시 읽을 위치만 보여 준다. 걸린 문장마다 korean-review.md의 유형 O, P, N, M의 기준으로 고칠지 정한다.
- 그대로 두는 경우: "~하다"가 목적어를 받지 않는 "~시키다"(향상시키다, 증가시키다)와 다른 대상이 하게 하는 "~시키다"(학습시키다), 자료의 어림을 한 번 남긴 문장, "만약 ~하더라도"처럼 양보로 쓴 "만약", 파일이나 표에 실제로 적어 넣은 기록("run.json에 JSON 형태로 적고")이다.

### A5.native_verbs, A7.see_judgment. 정보 전달 글의 동사 (0.9.0)
- 형태
  - A5.native_verbs: 사람 글이 같은 뜻에 한자어 동사를 10배 넘게 쓰는 고유어 동사. '사용' 뜻의 쓰다("이 방법을 씁니다", "쓸 수 있습니다", 수동 "쓰입니다"), 재다, 수치와 값 뒤의 "~로 두다", 고치다, 프로그램과 실험을 돌리다, 고르다
  - A7.see_judgment: 판단을 옮기는 "~라고 봅니다", "~것으로 봅니다", "X를 Y로 봅니다"
- 이유: 2022년 이전 합니다체 사람 글 57편은 "사용하다"를 1,000자당 2.97번, "쓰다"를 모든 뜻을 합쳐 0.22번 썼다. 측정하다와 재다는 0.04번과 0번, 설정하다와 두다는 0.55번과 0.04번이었다. A5.native_verbs에 걸리는 문장은 사람 글 1,000자당 0.096번, 0.4.0 예시 글 2.40번, 0.8.0 실행 글 0.72번이었다. "~라고 봅니다"는 사람 글 0.011번, 0.8.0 실행 글 0.45번이었다. 0.8.0까지의 "평이한 동사(…쓰다, 재다)" 규칙과 "저자들은 ~라고 봅니다"를 권한 예문이 원인이었다(사용자 2차 검토, 2026-10-18).
- 고치는 법: 그 자리의 뜻이 같으면 style-guide.md "정보 전달 글의 동사" 표의 말로 쓴다. 판단은 판단한 쪽이 한 일에 맞는 동사(추정합니다, 예상합니다, 해석합니다)로, "X를 Y로 봅니다"는 "X를 Y로 다룹니다"나 "간주합니다"로 쓴다. 기준 안으로 들어오면 멈춘다.
  - 전: 고정된 요청률에서 기본 샘플링으로 잰 end-to-end latency는 데이터셋마다 달랐습니다.
  - 후: 고정된 요청률에서 기본 샘플링으로 측정한 end-to-end latency는 데이터셋마다 달랐습니다.
  - 전: 저자들은 이 추세 때문에 메모리가 점점 더 큰 병목이 될 것으로 봅니다.
  - 후: 저자들은 이 추세 때문에 메모리가 점점 더 큰 병목이 될 것으로 예상합니다.
- 그대로 두는 경우: 글, 코드, 기록, 프롬프트를 쓰는 "쓰다", 시간과 비용을 쓰는 "쓰다", "신경 쓰다", 메모리와 디스크에 데이터를 쓰는 "쓰다", "~해 두다"와 "목표로 두다"처럼 값을 정하지 않는 "두다", "고른 성능"의 "고르다"다. lint는 이 형태를 세지 않는다. 넣다, 바꾸다, 나오다와 줄다, 늘다, 만들다는 사람 글도 자주 써서 세지 않는다. 사람 글도 이 고유어를 쓰므로 같은 동사를 모두 바꾸지 않는다.
- 위 두 전/후 예는 0.4.0 예시 글의 문장이다.

## 과교정하지 않기 (J8)

아래는 사람 글에서 더 많이 나오는 요소다. 패턴을 고치다가 이것까지 지우면 다른 방향으로 기계적인 글이 된다.

- 자료의 비교 내용을 담은 대조 문장
- 자료가 밝힌 불확실성을 옮긴 단서: "다만", "정확히는", "저자들은 ~라고 추정합니다"
- 괄호 보충: 용어 원어, 약어의 풀네임, 한 구절짜리 용어 설명, 단위 변환. 조건과 설명하는 절은 괄호가 아니라 문장으로 쓴다.
- 앞 문장과 주어가 같을 때의 주어 생략. 생략한 주어를 문장마다 다시 채우면 글이 늘어진다.
- 조건과 결과를 담은 긴 문장(80자 이상)
- 사람 글에 흔한 말: 살펴보다, 알아보다, 소개하다, 보다, 많다. 다만 한 글에서 같은 동사를 두 뜻으로 쓰면 한 뜻에만 남긴다(A21, style-guide.md의 "한 낱말은 한 뜻으로, 한 대상은 한 이름으로").
- "~를 통해", "~것이다", "~에 대해", "~을 위해". 다만 경로를 말할 때는 "거치는"이 더 자연스럽다("chemical synapse를 거치는 회피"). 2022년 이전 사람 글 87편에서 "~를 통해"는 1,000자당 0.94번, "~에 대해"는 0.59번 나왔다.
- 진행하다, 수행하다: 사람 글 87편에서 1,000자당 0.74번, 0.30번 나왔다.
- 고유어가 더 흔한 동사: 줄다, 늘다, 만들다. 2022년 이전 합니다체 사람 글 57편에서 줄다는 1,000자당 0.25번(감소하다 0.01번), 늘다는 0.17번(증가하다 0.07번), 만들다는 1.03번(생성하다, 구현하다 1.08번)이었다. 이 말을 한자어로 바꾸지 않는다.
- 사동이 맞는 "~시키다": "~하다"가 목적어를 받지 않는 말(향상시키다, 증가시키다)과 다른 대상이 하게 하는 말(모델을 학습시키다)
- 섹션을 여는 질문 1~3개, 사람 수준의 bold와 목록

한국어 점검 후보(A6.calque_check, A14.quoted_english_check, A18.negation_scope, A19)와 6단계 한국어 문장 점검에서 걸렸지만 사용자 검토에서 그대로 둔 표현이다. 이 표현을 바꾸면 과교정이다.

| 표현 | 그대로 두는 이유 |
|---|---|
| 문제가 남다, 할 일이 남다, 가능성이 남다 | 한국어에서 굳은 말이다 |
| notebook에 출력이 남아 있다, 값에 입력이 남아 있다 | 실제로 남아 있는 기록과 값이다 |
| 명시적으로 기록하지 않는다 | 원문 explicitly를 옮긴 말이지만 사람이 쓴 기술 글과 논문에서 그대로 쓴다 |
| A를 B로 읽다(해석하다) | 한국어에서 그대로 쓰는 용법이다. A7.read_as("~로 읽힙니다")와 다르다 |
| 검색창, 입력창 | 화면의 창을 가리킨다 |
| learning window | 원어 용어로 쓰고 처음 나올 때 정의했다 |
| 최댓값을 가진다, 큰 값을 가진다 | 수학에서 굳은 표현이다. 속성의 "~를 가지고 있다"(A14)와 다르다 |
| ~에 해당하다 | "대응하다"라는 동사 용법이다. "해당 자료" 같은 지시 용법과 다르다 |
| 원문은 "..."입니다(문장째 인용) | 근거를 밝히는 인용 형식이다 |
| 시간 척도, 시간 규모 | 둘 다 한국어에서 쓰는 말이다. 한 글 안에서만 하나로 맞춘다 |
| 시냅스를 맺다 | 자연스러운 말이다. 다른 문장의 표기와 맞추려고 "시냅스를 내다"로 바꾸지 않는다 |
