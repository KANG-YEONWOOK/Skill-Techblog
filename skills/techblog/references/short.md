# 짧은 글 모드

영어로 쓴 짧은 글을 같은 구조, 순서, 분량, 사실 그대로 한국어로 옮긴다. Slack에 올리는 질문, 검토 요청, 답글, 보고, 진행 알림의 고정 문형, 작업 이름처럼 도구가 만든 글이 대상이다. 블로그 아티클을 쓰는 1~8단계, fact sheet, subagent 후처리는 하지 않는다. 한 글을 몇 분 안에 끝내는 것이 목표다.

## 입력

- **원문:** 영어 Markdown 파일. 여러 개를 한 번에 받을 수 있다.
- **출력:** `-o <경로>`. 원문이 하나면 파일 경로, 여럿이면 폴더다. 폴더면 원문마다 `<원문 파일 이름에서 확장자를 뺀 이름>.ko.md`로 저장한다. `-o`가 없으면 원문 옆에 같은 규칙으로 저장한다.
- **용어표(선택):** `--terms <JSON 경로>`. `{"영어": "한국어"}` 형식이다. 원문에 영어 표기가 나오면 결과에는 한국어 표기를 쓴다. 버튼 이름, 단계 이름, 작업 이름처럼 화면에 보이는 말을 맞추는 데 쓴다. 대문자가 있는 표기(버튼 이름 `Keep`)는 쓴 그대로 찾고, 모두 소문자인 표기(`blocked`)는 대소문자를 가리지 않고 찾는다. 코드 블록과 인라인 코드 안은 찾지 않는다.
- **어투:** Default(합니다체)가 기본이다. `casual`이 있으면 해요체로 쓴다.

## 옮기는 규칙

1. **구조를 그대로 둔다.** 문단, 목록 항목, 헤딩, 표, 굵은 글씨, 링크를 원문 순서대로 둔다. 목록 항목을 합치거나 나누지 않는다. 문장을 더하거나 빼지 않는다.
2. **덧붙이지 않는다.** 제목, 도입, 마무리, 참고자료, 분석, 설명을 더하지 않는다. 원문이 말하지 않은 판단이나 예상을 쓰지 않는다.
3. **원문 그대로 두는 것:** 코드 블록, 인라인 코드(`` `…` ``), URL, 파일 경로, 명령, 식별자, 숫자(아라비아 숫자 그대로), Slack 멘션(`<@U…>`, `<#C…>`, `<!here>`), `{link}`나 `{request}` 같은 자리표시자. 자리표시자 안의 말도 옮기지 않는다.
4. **읽는 사람에게 직접 하는 말은 원문대로 옮긴다.** 질문, 요청, "원하시면", "요청하신 대로"처럼 읽는 사람을 부르는 말은 이 모드에서 허용한다.
   - Default 글의 요청은 "~해 주세요"로 쓴다. "~해 주십시오"는 쓰지 않는다.
   - Default 글의 질문은 "~할까요?", "~습니까?", "~인가요?" 가운데 문맥에 맞는 것을 쓴다.
5. **한국어로 일하는 사람이 업무 메시지에서 실제로 쓰는 말로 쓴다.** 영어 어순과 구문을 따라가지 않는다. [style-guide.md](style-guide.md)의 문장 규칙과 같은 기준이다. 특히 다음을 피한다.
   - "그것은", "~에 의해", "~을 가지고 있다", "중요한 역할을 한다" 같은 번역투
   - "~되어지다" 같은 이중 피동
   - 문장 첫머리의 "이러한", "이를 통해"
   - em dash(—), 세미콜론, 이모지. 원문에 있으면 문장을 나누거나 쉼표로 바꾼다.
6. **용어:** 용어표가 있으면 그대로 따른다. 없으면 한국어 업무 글에서 쓰는 표기를 쓰고, 원문의 도구에서 영어 그대로 쓰는 말(branch, merge, PR, commit, push)은 영어로 둔다.

## 순서

1. 원문을 끝까지 읽는다.
2. 위 규칙대로 한국어로 옮겨 출력 경로에 저장한다.
3. 결과마다 검사한다. `<스킬 절대 경로>`는 이 문서를 읽은 `SKILL.md`의 디렉터리다.

   ```text
   python3 "<스킬 절대 경로>/scripts/lint_ko.py" "<결과>" --short --source "<원문>" --tone default
   ```

   용어표가 있으면 `--terms "<용어표>"`를 붙이고, Casual이면 `--tone casual`로 바꾼다.
4. 판정이 FAIL이면 걸린 항목을 고치고 다시 검사한다. 세 번까지 한다.
   - F로 시작하는 항목은 원문 대조다. 빠지거나 바뀐 코드, URL, 숫자, 멘션, 자리표시자, 목록 항목, 헤딩, 용어를 원문대로 되돌린다.
   - 나머지는 문체 항목이다. "고치는 방향"대로 고친다.
5. 결과를 보고한다. 파일마다 경로와 마지막 판정을 쓰고, 세 번 고쳐도 남은 항목이 있으면 그 항목을 쓴다. 작업 파일은 만들지 않는다.

검사를 실행할 수 없으면 위 규칙으로 직접 점검하고, 자동 검사를 하지 못했다고 보고한다. 실행 환경의 차이는 [runtime.md](runtime.md)를 따른다.
