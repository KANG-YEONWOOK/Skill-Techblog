# 처리 모델을 확인하는 방법

모델은 입력 신호를 받아 출력 신호를 계산하는 식입니다. 이 글은 글쓰기 평가용 가상 자료인 "설명용 처리 모델 노트"를 바탕으로 모델의 계산을 기록과 비교하는 방법을 설명합니다.

## 연결표의 범위

연결표는 처리 장치 사이의 연결을 나타낸 표입니다. 접점은 두 처리 장치가 직접 연결되는 지점입니다.

노트 속 연구팀은 신호 일부가 접점 밖에서 전달된다는 점과 다른 신호가 긴 연결을 따라 여러 영역에 전달된다는 점을 연결표의 한계로 듭니다.

## 기록으로 맞추고 확인하기

모델은 입력 신호를 받아 출력 신호를 계산하는 식이며 parameter는 그 식에서 조정할 수 있는 값입니다. 연구팀은 첫날의 입력 신호를 모델에 넣고 모델이 계산한 출력 신호가 첫날에 측정한 출력 신호와 비슷해지도록 parameter를 조정했습니다. 첫날의 출력 신호를 재현했다는 사실만으로 다른 날의 출력 신호도 예측한다고 결론 내릴 수는 없습니다.

둘째 날에는 첫날에 정한 parameter를 고정한 모델이 둘째 날의 입력 신호로 출력 신호를 예측했습니다. 연구팀은 모델이 예측한 둘째 날의 출력 신호를 둘째 날에 측정한 출력 신호와 비교했습니다.

둘째 날 기록은 parameter를 정하는 데 사용되지 않았습니다. 값을 정할 때 사용하지 않은 둘째 날의 기록과 모델의 예측을 비교하는 절차가 이 사례의 검증입니다.

## 순서를 바꾼 입력

token은 입력 목록의 개별 항목이고 벡터는 여러 수를 순서대로 담은 목록입니다. 모델은 입력 목록의 모든 token을 함께 참고해 token마다 출력 벡터를 계산합니다. 예시 입력 목록의 token 이름은 dog, bites, man입니다.

여기서는 token이 입력 목록의 어디에 있는지를 나타내는 위치 정보를 더하지 않습니다. causal mask는 각 token이 자신보다 뒤에 있는 token을 참고하지 못하게 하는 제한이며 이 설명의 모델은 causal mask를 사용하지 않습니다.

위치 정보와 causal mask가 없는 이 조건에서는 입력 순서를 dog, bites, man에서 man, bites, dog로 바꿔도 같은 token에 대응하는 출력 벡터의 값은 같습니다. 출력 목록에서 각 벡터가 놓이는 위치는 그 벡터에 대응하는 token의 입력 위치와 함께 바뀝니다.

| token | 변경 전 입력과 출력 목록의 위치 | 변경 후 입력과 출력 목록의 위치 | 해당 token의 출력 벡터 값 |
|---|---|---|---|
| dog | 첫 번째 | 세 번째 | 변경 전과 같음 |
| bites | 두 번째 | 두 번째 | 변경 전과 같음 |
| man | 세 번째 | 첫 번째 | 변경 전과 같음 |

위치 정보와 causal mask가 없는 조건에서 입력 순서를 바꾸면 출력 목록에서 벡터의 순서가 바뀝니다. 각 벡터 안에 들어 있는 수의 순서는 바뀌지 않습니다.

causal mask를 사용하는 경우에는 입력 순서를 바꾸면 각 token이 참고할 수 있는 token이 달라져 출력 벡터 값도 달라질 수 있습니다.

## 마치며

첫날에 측정한 출력 신호를 재현하도록 parameter를 조정하는 일과 그 값을 고정한 모델이 예측한 둘째 날의 출력 신호를 둘째 날에 측정한 출력 신호와 비교하는 일은 구분해야 합니다. 이 노트에는 둘째 날의 예측이 측정값과 얼마나 일치했는지 설명되어 있지 않아 예측의 정확도를 판단할 수 없습니다.

입력 순서를 바꿔도 같은 token의 출력 벡터 값이 유지된다는 설명은 위치 정보와 causal mask를 모두 사용하지 않는 조건에 해당합니다. causal mask를 사용하면 출력 벡터 값도 달라질 수 있고, 위치 정보를 더한 경우에도 같은 값이 유지된다고 이 노트는 주장하지 않습니다. 실제 출력 벡터의 수치도 노트에 없으므로 순서 예시는 각 token에 대응하는 벡터의 값과 위치를 구분해서 읽어야 합니다.
