# dogfooding 기록

실행 조건과 평가 방법은 [README.md](README.md)에 있다. 모든 실행은 Claude Code 2.1.289, `--model opus --effort xhigh`(S3만 sonnet), 사용자 CLAUDE.md를 끈 상태다. judge는 sonnet이다.

표의 지표
- lint G/F/W: Gate 위반 / FAIL / WARN 수
- 목록, bold, 셋 묶음, 연결어미 쉼표, 부정 대구: 스킬 없는 Claude 출력이 사람 글 p90을 넘었던 지표(사람 글 p90: 목록 0.25, bold 3.23/1,000자, 셋 묶음 1.90/1,000자, 연결어미 쉼표 0.33, 부정 대구 2문장)
- 종결 반복: 같은 종결이 4문장 이상 이어진 횟수(사람 글 p90 5)
- style 평균: style judge J2~J6, J8 평균(0~2), 2회 실행
- J7/1k: style judge가 "AI가 쓴 것처럼 읽힌다"고 인용한 문장 수(1,000자당, 인용이 본문에 있는 것만)
- fidelity: 자료로 뒷받침되지 않는 주장 / 자료와 다른 주장
- pairwise: 같은 자료의 iteration 0 글과 순서를 바꿔 두 번 비교. current는 두 번 모두 이번 글을 고른 경우, split은 순서에 따라 갈린 경우

pairwise에서 A가 갈린 이유(judge 근거 요약)
- iteration 0 글은 도입을 자료의 구체 장면("주인공 이름은 Elara이고 … 심장이 갈비뼈를 두드려요")으로 시작했고, 이번 글은 수치("85,513배 … 1,192배")를 연달아 놓고 "결론부터 말하면"으로 넘어가 보도자료처럼 읽혔다.

- 반대 순서에서는 iteration 0 글의 요약 표지("짚어 둘 점이 세 가지 있어요"), 부정 대구, 은유("손잡이는 β 하나뿐")가 더 크게 보여 이번 글이 이겼다.

원인 분석
- 종결 반복: Casual 글은 Default 초안의 종결부만 바꾸므로 초안의 종결이 "~합니다/~했습니다"에 몰리면 Casual도 "~해요/~했어요"만 이어진다. A의 현재형 해요체 비율은 50%로 사람 해요체 글(27%)의 두 배였다.
- 도입: style-guide가 "독자 상황이나 문제에서 시작"만 정하고 수치 나열을 막지 않았다.
- 분석 부족: 스킬이 "자료에 있는 사실만"을 강조해서 자료에 근거한 해석(설계 이유, 표의 수치 비교)까지 줄었다.
- S1의 근거 없는 문장: style-guide의 "자료가 남긴 열린 질문으로 끝낸다"를 따라 자료가 열린 질문이라고 하지 않은 내용을 열린 질문으로 썼다.

## iteration 2 변경 (도입, 분석, 리듬, 용어)

- style-guide, SKILL.md
  - 도입은 자료의 구체 장면이나 독자 상황에서 시작하고 첫 문단에 수치를 연달아 놓지 않는다.
  - "자료를 읽은 사람의 분석" 절 추가: 설계 이유, 표의 수치 비교, 실험 조건에서 나오는 적용 범위. 근거를 함께 쓰고 자료에 없는 수치·경험·일반론은 만들지 않는다.

  - 한국어로 굳어진 용어(어휘, 불용어, 학습, 추론)는 한국어로 쓴다. iteration 1 글은 vocabulary, stopword를 영어로 남겼다.
- lint
  - A8.ending_run4(같은 종결 4문장 이상 연속)를 참고 지표에서 판정 지표로 올렸다(사람 글 기준 PASS ≤6, WARN ≤10).
  - A3에 평가형 강조("~점이 흥미롭습니다", "결과는 ~ 극적입니다", "진짜 강점은") 패턴을 추가하고 사람 글로 기준치를 다시 잡았다(PASS ≤2). holdout 통과율은 86%로 같다.

## iteration 3 변경 (문장 주어, 마무리, 분석의 정보성)

- 사실은 기술·방법·결과를 주어로 쓰고 "저자들은", "논문은"은 저자의 주장·추정·판단을 옮길 때만 쓴다(본문 문장의 10% 이하). lint에 A16.source_subject_share(policy, PASS ≤0.10)를 추가했다.
- "마치며"는 3~5문장으로 쓰고 본문 수치를 다시 늘어놓지 않는다.
- 도입의 "이 글에서는 ~를 정리합니다"는 한 문장으로 쓰고 다룰 항목을 셋 이상 늘어놓지 않는다.
- 분석 문장도 deletion test를 통과해야 한다(새 수치 비교나 조건이 있어야 한다). 자료의 조건에서 추론한 내용은 추론임을 문장에 드러낸다.
- "모두", "항상", "전혀", "유일한" 같은 범위 표현은 자료가 그렇게 쓴 경우에만 쓴다.
- 셋 묶음 검출에서 수치·영문 이름·인용이 든 나열을 뺐다(사람 글로 다시 보정, PASS ≤1.62/1,000자).
- style-guide와 SKILL.md의 예시 문장에 남아 있던 테스트 자료(Antislop)의 사실을 가상 자료의 예시로 바꿨다. 예시 문장이 테스트 글에 섞여 들어가는 것을 막기 위해서다.
- 참고: rubric.md는 근거 자료로 B·C·D 케이스의 논문 수치를 인용한다. 스킬이 점검 단계에서 rubric을 읽으므로 이 세 논문을 정리할 때는 rubric의 요약이 영향을 줄 수 있다. 이 영향이 없는 자료(S1, E, S2)로도 같은 기준을 확인한다.

- fidelity judge가 추론임을 드러낸 문장도 근거 없음으로 판정해서, 사람 글이 하는 적용 고찰과 fidelity 기준이 부딪혔다.

- iteration 6에서 넣은 문단 지시 "전환 문장, 핵심 수치, 절의 결론은 한 문장 문단으로 둔다"와 "한 문단에는 사실 하나와 그 근거나 결과까지만 쓴다"가 원인이다. 모델은 문단 수를 늘리려고 절마다 결론 한 줄과 전환 질문을 따로 문단으로 만들었고, 사실 하나씩 짧은 문장으로 끊었다. 사람 글의 한 문장 문단은 대부분 수치나 사실 하나를 담은 문단이다.
- fidelity 3건은 독자 환경(한국어, 토큰화)에 대한 문장을 조건이나 가능성 없이 단정한 경우다. SKILL.md의 "추론임을 문장에 드러낸다"는 자료에서 추론한 문장에만 적용되는 것처럼 읽혀서 독자 환경에 대한 일반 지식 문장은 단정으로 남았다.

held-out 6건 중 4건(C, D, E, F)을 이 버전으로 실행했다. 네 글 모두 lint Gate·FAIL·WARN 0이었고 D와 F(`--retone`)는 tone_check를 통과했다. 위 회귀를 확인한 뒤 나머지 2건은 중단했고, held-out round는 iteration 7 버전으로 다시 실행했다.

## iteration 7 변경 (iteration 6 문단 지시의 회귀 수정)

계획의 상한은 iteration 6이었지만, iteration 6의 회귀가 이 스킬의 지시문에서 생긴 것이라 지시를 고친 버전을 한 번 더 확인한다.

- 문단 지시를 "문단은 2~3문장 단위로 나누고, 네 문장 넘게 이어지면 내용이 바뀌는 곳에서 나눈다. 한 문장 문단에는 수치, 정의, 조건 같은 사실을 쓴다. 앞 문단을 정리하는 문장이나 다음 내용을 예고하는 질문을 한 문장 문단으로 만들지 않는다. 문단을 나눌 때 문장을 짧게 자르지 않는다"로 바꿨다(SKILL.md, style-guide, ai-patterns, lint hint). A8.single_para_ratio의 하한은 그대로 둔다.
- 적용 절에서 독자 환경에 대한 내용도 조건("~라면")이나 가능성("~수 있습니다")으로 쓰게 했다. 점검 단계의 대조 항목에 "방법의 세부(토큰화 방식, 단위, 설정값)가 자료에 있는가"를 더했다.

## 종료 판단

iteration 7에서 멈춘다. 근거는 다음과 같다.

- 남은 문제
